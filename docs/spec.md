# ColorfulTalk pico LSI 仕様書

> シリーズ全体の仕様書: [ColorfulTalk](https://github.com/ukagaka-irono/ColorfulTalk)（`docs/spec/pico-lsi.md` と同じ内容）

ColorfulTalk nano を ATmega328P に載せた、1 チップの音声合成 LSI の設計図です。
ホストのマイコンや PC から、ローマ字の記号列を 1 行送るだけで話します。

## 主な仕様

| 項目 | 内容 |
|---|---|
| 版 | 1.0.0（nano 1.0.0 を内蔵） |
| チップ | ATmega328P（DIP-28 / TQFP-32） |
| 電源・クロック | 5V、16MHz 水晶 |
| 音声出力 | PD3（OC2B, 5 番ピン）から 62.5kHz の PWM。2 段の RC ローパスで音声に戻す |
| 合成 | ColorfulTalk nano（8kHz） |
| 入力 | UART 9600bps 8N1、または I2C スレーブ（アドレス 0x2E） |
| 記号列 | ローマ字記号列（[koe-roman.md](koe-roman.md)）。1 行 127 文字まで |
| 状態出力 | PD2（4 番ピン）: 話している間 High（BUSY） |
| 声・話速 | 4 種の声（`#V`）、話速 50〜200（`#S`）。電源を入れると女声・100 |
| フラッシュ / RAM | 約 10KB / 約 700 バイト（静的 489 バイト＋スタック 約 210 バイト） |

## ピン配置（DIP-28）

| ピン | 名前 | 用途 |
|---|---|---|
| 1 | PC6 / RESET | 10kΩ で 5V へ。ISP |
| 2 | PD0 / RXD | UART 受信（ホストの TX へ） |
| 3 | PD1 / TXD | UART 送信（ホストの RX へ） |
| 4 | PD2 | BUSY 出力 |
| 5 | PD3 / OC2B | 音声 PWM 出力 |
| 7, 20 | VCC, AVCC | 5V（それぞれ 100nF で GND へ） |
| 8, 22 | GND | |
| 9, 10 | XTAL1, XTAL2 | 16MHz 水晶（各 22pF で GND へ） |
| 17, 18, 19 | MOSI, MISO, SCK | ISP 書き込み |
| 27, 28 | PC4 / SDA, PC5 / SCL | I2C |

回路図は [hardware/schematic.svg](../hardware/schematic.svg)、部品表は [hardware/bom.md](../hardware/bom.md)。

## UART のコマンド

改行（CR または LF）までを 1 行として受け取ります。処理が終わるたびに `>` を返します（起動時にも 1 回返します）。

| 送る | 動作 | 返事 |
|---|---|---|
| 記号列 | 話す | 話し終わったら `>` |
| `#V n` | 声を選ぶ（0 女声, 1 男声, 2 子ども, 3 ロボット） | `>` |
| `#S n` | 話速（50〜200、100 が標準） | `>` |
| `#X` | 話すのをやめる（話している途中でもすぐ止まる） | `>` |
| `#?` | 版を返す | `ColorfulTalk pico 1.0.0` と `>` |

- 記号列やコマンドに誤りがあるときは `E<エラーコード>,<位置>` を返し、続けて `>` を返します（例: `konnichiwa@` → `E3,10`）
- 話している間に送った行は、話し終わってから処理します（`#X` だけはすぐ処理）。先に受け取れるのは 1 行までで、
  それ以上は捨てます。`>` を待ってから次の行を送ってください
- 1 行が 127 文字を超えると `E9,127` を返します

## I2C

アドレス 0x2E のスレーブです（7bit アドレス、標準モード 100kHz）。

| 操作 | 内容 |
|---|---|
| 書き込み | 記号列またはコマンドを書き込み、STOP で 1 行の終わり（UART の改行と同じ） |
| 読み出し 1 バイト目 | 状態: 0 = 待機、1 = 話している、2 = 次の行を受け取り済み |
| 読み出し 2 バイト目 | 直近のエラーコード（0 = なし） |

I2C で送った行への返事（`>` や `E…`）も UART に出ます。I2C だけで使う場合は、状態バイトか BUSY ピンで終わりを確かめてください。

## 動作の仕組み

- メインループ: nano で 1 サンプルずつ合成し、64 サンプルのリングバッファを満たす。32 サンプル溜まってから鳴らし始める
- Timer1 の割り込み（8kHz）: バッファから 1 サンプル取り出して OCR2B（PWM のデューティ）に書く
- 合成は 1 サンプル平均 約 1,400 サイクル（16MHz で 8kHz に必要な 2,000 サイクル以内）。処理が集中する瞬間はバッファで吸収する

## 確認したこと

ファームウェアをシミュレータ（avr8js）で ATmega328P として動かし、UART から操作して確かめました（[tests/check.sh](../tests/check.sh)）。

| 項目 | 結果 |
|---|---|
| PWM に書かれた値 | PC 版 nano の 8bit 出力とビット単位で一致（女声・話速 100、男声・話速 150 の 2 文） |
| 合成の遅れ（バッファが空になった回数） | 0 回 |
| 発話の長さ | 15,488 サンプル → 1.94 秒（実時間どおり） |
| `#?` `#V` `#S` `#X`、誤りの返事 | 仕様どおり |

I2C はシミュレータがスレーブ動作に対応していないため、コードのみで未確認です。実機での確認は利用者にお願いします。
